# LLM Benchmark Matrix — 前端展示逻辑设计方案 v3.0

> 2026-06-19 · 基于 AA 数据驱动架构（209 模型 × 15 benchmark + LMArena 待入库）

---

## 一、设计目标

**核心定位：选型工具，不是排行榜展示工具。**

- 排行榜的"最强"是参照系（了解前沿水平），不是选型目标
- 真正有价值的是：跨维度聚合视角 + 场景化对比 + 深度下钻
- 信息密度优先：一眼扫全，点击下钻，不用逐表翻阅

**用户心智模式：**
| 模式 | 典型问题 | 对应视图 |
|------|---------|---------|
| 找参照 | "最强模型发展到什么水平了？" | 排行榜 |
| 看全貌 | "GPT-5.5 在所有维度表现如何？" | 下钻面板 |
| 做对比 | "GPT-5.5 vs Claude 5 vs Gemini 3？" | 对比视图 |
| 按场景选 | "我做开发，哪个模型最适合？" | 场景预设 |

## 二、五维度体系

### 维度定义

| 维度 | 英文 key | 中文 | 核心问题 | 数据来源 |
|------|---------|------|---------|---------|
| 事实准确 | factual | 事实准确 | 知识广度与深度推理 | Omniscience/GPQA/HLE/AIME |
| 工作流 | workflow | 工作流 | 多行业实际应用能力 | GDPVal/IFBench/TAU/Agentic Index |
| 工程能力 | engineering | 工程能力 | Agent 编程相关 | TerminalBench/SciCode/LiveCodeBench/Coding Index |
| 成本 | cost | 成本 | 实际工作消耗 | cost_per_task_usd（核心）+ 定价（辅助） |
| 人类偏好 | preference | 人类偏好 | 真实用户主观评价 | LMArena Text Elo（待入库） |

### 维度内 benchmark 分组（二级自定义）

每个维度内的 benchmark 可按能力侧重分组，支持场景化聚焦：

**事实准确：**
- 知识广度：Omniscience（综合知识指数）
- 深度推理：HLE（人类终极考试）、GPQA（研究生问答）
- 数学能力：AIME 2025、AIME（历史）

**工作流：**
- Agent 能力：GDPVal（Elo + 归一化）、Agentic Index
- 指令遵循：IFBench
- 行业场景：TAU-2 Banking、TAU Banking（旧版）

**工程能力：**
- Agent 编码：TerminalBench Hard
- 纯代码：SciCode、LiveCodeBench、Coding Index

**成本：**
- 实际消耗：cost_per_task_usd（单任务成本，核心排序依据）
- 定价参考：pricing_input/output（$/M token，辅助）

**人类偏好：**
- 主观评价：LMArena Text Elo（Elo 评分 + 排名 + 票数）

### 场景预设（用户自定义，非固定预设）

**设计决策：不内置固定预设，改为用户自定义方案 + 浏览器缓存。**

用户可调整各维度权重 + 维度内 benchmark 聚焦，保存为自定义方案：
- 方案名：用户输入
- 存储：localStorage（持久化，无 7 天限制问题，除非用户清缓存）
- 可保存多个方案
- 默认权重：factual 0.25 / workflow 0.25 / engineering 0.20 / cost 0.15 / preference 0.15

**典型场景示例（用户可参考创建）：**
| 场景 | factual | workflow | engineering | cost | preference |
|------|---------|---------|-------------|------|------------|
| 咨询严肃问题 | 0.45 | 0.15 | 0.10 | 0.10 | 0.20 |
| 开发 | 0.15 | 0.20 | 0.45 | 0.10 | 0.10 |
| 子 Agent | 0.10 | 0.35 | 0.30 | 0.20 | 0.05 |
| PPT 文案 | 0.15 | 0.15 | 0.05 | 0.15 | 0.50 |

```
├─────────────────────────────────────────────────────────────┤
│ 筛选栏：搜索 + 厂商筛选 + 高级筛选（时间/排名/开源/多模态）      │
├─────────────────────────────────────────────────────────────┤
│ 统计栏：132 模型 · 15 评测 · 2267 数据点 · 5 维度              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│                    主内容区（按视图切换）                      │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 视图 1：排行榜（默认）

**导航：两级 tabs**
```
[事实准确] [工作流] [工程能力] [成本] [人类偏好]     ← 一级：5 维度
 ┌──────────────────────────────────────────┐
 │ ○Omniscience  GPQA  HLE  AIME25  AIME    │  ← 二级：该维度下 benchmark chips
 │ (active)                                   │
 └──────────────────────────────────────────┘
```

- 一级 tab 永远 5 个，横排无压力
- 二级 chips 3-5 个，当前选中高亮
- 成本维度特殊：二级 chips 为 [实际消耗] [定价参考]

**表格行结构：**
```
┌──────┬────┬────────────────────────┬──────┬─────────────┬───────┐
│ 标记  │排名│ 模型                    │ 分数 │ 子维度       │ 操作   │
├──────┼────┼────────────────────────┼──────┼─────────────┼───────┤
│👁 🔓  │ 1 │ GPT-5.5 (xhigh)        │ 85.3 │ 准确率 82%  │ ⚖️ ▼  │
│👁 🔒  │ 2 │ Claude 5 (xhigh)       │ 83.7 │ 准确率 80%  │ ⚖️ ▼  │
│🔇 🔓  │ 3 │ Gemini 3 Pro           │ 81.0 │ 准确率 78%  │ ⚖️ ▼  │
└──────┴────┴────────────────────────┴──────┴─────────────┴───────┘
  ↑ 标记列：多模态 + 开源状态
  ↑ ⚖️ = 加入对比  ▼ = 展开下钻
```

**标记列（最左侧，2 个图标，精简表达）：**

设计原则：标签头精简、占位小、足够表达意思。其他模块内信息位置允许可内容多一点。

| 标记 | 含义 | 图标 | 说明 |
|------|------|------|------|
| 多模态 | 常规多模态（视觉+音频等） | 🎨 | supports_vision 或 supports_audio |
| TTS | 仅语音输出（专用模型） | 🔊 | size_class 含 TTS 或特殊标记 |
| 开源 | 开源模型 | 开 | open_source=open |
| 闭源 | 闭源模型 | 闭 | open_source=proprietary |
| 混合 | 混合许可 | 混 | open_source=hybrid |

说明：市面上无模型只支持视觉或只支持语音，多模态标记只需区分"常规多模态"和"TTS 专用"两种。开源状态用单字"开/闭/混"替代图标，占位最小。

**高级筛选栏（筛选栏右侧展开）：**
- 发布时间：最近 30 天 / 90 天 / 半年 / 全部
- 排名范围：仅前 10 / 前 20 / 前 50 / 全部
- 开源状态：全部 / 仅开源 / 仅闭源
- 多模态：全部 / 支持视觉 / 支持音频
- 推理级别：全部 / 仅默认 / 指定级别

- 点击单元格 → 展开该模型下钻面板，定位到该 benchmark
- 支持厂商筛选 + 搜索 + 高级筛选
- 默认按综合指数降序（综合指数 = 5 维度加权平均，按当前方案权重）

### 视图 4：我的方案

**用户自定义权重方案管理**

- 已保存方案列表（卡片式）
- 每个方案：名称 + 5 维度权重 + 维度内 benchmark 聚焦设置
- 新建方案：滑块调整 5 维度权重 + 勾选每个维度关注的 benchmark
- 应用方案 → 影响排行榜排序和矩阵总览的综合指数计算
- 方案存储于 localStorage，可导出/导入 JSON

## 四、详情下钻面板（核心）

### 触发方式
- 排行榜：点击模型行 ▼ 按钮
- 矩阵总览：点击任意单元格
- 对比视图：点击模型列头

### 最左侧：子维度信息

展示当前上下文 benchmark 的完整子维度数据：
- 主分数 + 排名（#X/总数）
- 该 benchmark 特有的子维度（如 Omniscience 的准确率/幻觉率）
- 通用辅助数据：input_tokens / output_tokens / reasoning_tokens / cost_usd
- 数据来源 + 置信度 + 观测日期
- needs_manual_review 标记（如有）

### 中间：其他维度排名 + 快捷导航（核心交互）

**展示逻辑：**
- 5 个维度卡片，每个显示该维度的**加权综合分数 + 排名**
- 当前所在维度的卡片高亮标记
- **点击维度卡片 → 展开该维度下的 benchmark 子项列表**：
  ```
  ┌──────────────────┐
  │ 事实准确  #2/209  │  ← 维度卡片（收起态）
  │ 85.3 (主权重)     │
  └──────────────────┘
  点击后展开：
  ┌──────────────────┐
  │ 事实准确  #2/209  │
  │ 85.3 (主权重)     │
  │ ──────────────── │
  │ Omniscience 85.3  │  ← 子项：benchmark 分数 + 排名
  │   #1/209  →       │  ← 点击 → 跳转到 Omniscience tab
  │ GPQA        78.2  │
  │   #3/209  →       │
  │ HLE         62.0  │
  │   #2/209  →       │
  │ AIME 2025   90.0  │
  │   #1/209  →       │
  └──────────────────┘
  ```
- **再点击子项 → 跳转到对应 benchmark tab，定位到该模型行并高亮**
- 跳转后下钻面板保持打开，最左侧更新为新 benchmark 的子维度

**交互层级：维度卡片 → 展开子维度 → 点击跳转 = 三级下钻**

### 右侧：多维度信息

- **5 轴雷达图**：ECharts 渲染，5 个维度各一轴，数值为归一化后的 0-100
- **综合指数**：按当前方案权重计算的加权总分 + 全局排名
- **推理级别对比**：同一模型不同推理级别的分数横向对比（仅推理模型显示）

## 五、筛选与排序

### 筛选维度

| 筛选项 | 类型 | 选项 |
|--------|------|------|
| 搜索 | 文本 | 模型名 / model_id 模糊匹配 |
| 厂商 | 多选 chip | 9 家厂商 + 其他 |
| 发布时间 | 单选 | 最近 30 天 / 90 天 / 半年 / 全部 |
| 排名范围 | 单选 | 前 10 / 前 20 / 前 50 / 全部 |
| 开源状态 | 单选 | 全部 / 仅开源 / 仅闭源 |
| 多模态 | 单选 | 全部 / 支持视觉 / 支持音频 |
| 推理级别 | 多选 | 默认 / xhigh / high / medium / low / non-reasoning |

### 排序逻辑

- 排行榜：按当前 benchmark 的 score_raw 降序（成本维度按 cost_per_task_usd 升序）
- 矩阵总览：默认按综合指数降序，可点击任意列头切换排序
- 对比视图：固定按综合指数降序

## 九、备选思路保留

以下方案在讨论中提出但未采用，记录以备后续参考：

### 备选 A：左侧固定 benchmark 树 + 右侧内容（方案 B）

- 左侧 200px 侧边栏，benchmark 按维度分组树状展示
- 所有 15 个 benchmark 一眼可见，零点击定位
- **未采用原因：** 占用 200px 宽度压缩表格空间；移动端不友好
- **可复用场景：** 若未来 benchmark 数量增长到 30+，横向 chips 无法承载时可重新考虑

### 备选 B：搜索驱动 + 收藏

- 顶部搜索框可搜 benchmark 名或模型名
- benchmark chips 横向滚动，常用可收藏置顶
- **未采用原因：** 首次使用无收藏，发现性差；横向滚动不够直觉
- **可复用场景：** 可作为高级筛选的补充，搜索框已保留在筛选栏

### 备选 C：固定场景预设（非用户自定义）

- 内置 4 个场景预设（咨询/开发/子Agent/文案）
- **未采用原因：** 用户明确要求改为自定义方案 + localStorage 存储
- **可复用场景：** 自定义方案视图中的"典型场景示例"表格已保留这些参考值
